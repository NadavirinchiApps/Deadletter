# EDA008 — Dead-letter queue retention is shorter than its source

**Condition:** Any message that fails late in the source queue's retention window.

## What it detects

Compares a dead-letter queue's `MessageRetentionPeriod` against that of the
queue that feeds it.

Redrive does not reset a message's enqueue timestamp. A message keeps the age it
accumulated on the source queue, so its remaining life in the dead-letter queue
is `dlq_retention - age_at_failure`, not the full DLQ retention. A dead-letter
queue that does not outlive its source deletes a late-failing message almost
immediately — and a message that arrives in a DLQ is, by definition, one nobody
has looked at yet.

## What the finding can carry

| Axis | Values this rule uses |
|---|---|
| `impact` | `LOSS` |
| `confidence` | `CONFIRMED` |
| `basis` | `REQUIREMENT` |
| Can it BLOCK under `--policy default`? | Yes — when the short retention was written, not inherited |

`impact` is what breaks, `confidence` is how well the condition is known, and
`basis` is whether the threshold is AWS's rule or AWS's advice. The verdict is
computed from those three by the policy you choose — the rule never sets it.

## What it rests on

- [Amazon SQS dead-letter queues](https://docs.aws.amazon.com/AWSSimpleQueueService/latest/SQSDeveloperGuide/sqs-dead-letter-queues.html)
- [Amazon SQS quotas: message retention](https://docs.aws.amazon.com/AWSSimpleQueueService/latest/SQSDeveloperGuide/sqs-quotas.html)

## What it cannot know

Nothing material. Both values are read from the template, the arithmetic is
AWS's documented behaviour, and this is one of the five rules that can block
under the default policy — but only when the short retention was written by the
author rather than inherited from the AWS default.

## Also reported by

Nothing measured. See [the benchmark](../benchmark.md) for how that was
established, and against which versions of which tools.

## Example

From `tests/fixtures/EDA008/violating.yaml`:

```text
[BLOCK] EDA008 - Dead-letter queue retention is shorter than its source
  OrdersDlq MessageRetentionPeriod is 86400s, while its source OrdersQueue retains messages for 345600s. Required: more than 345600s, up to the 1209600s maximum. Consequence: redrive does not reset a message's age, so a message older than 86400s when it fails is deleted from the dead-letter queue immediately, and every message loses 259200s of the window it should have had.
  basis: confirmed requirement | impact if it bites: loss
```

## Suppressing it

Suppressions live in the template, beside the resource they excuse. A reason is
mandatory, `expires` is honoured, and nothing is deleted — a suppressed finding
stays in the JSON report and is marked in SARIF.

```yaml
Resources:
  OrdersDlq:
    Metadata:
      deadletter:
        ignore:
          - rule: EDA008
            reason: Why this is acceptable here, and who decided.
            expires: 2027-01-31   # optional
```
