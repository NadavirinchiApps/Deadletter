# EDA005 — Poison record blocks the shard until expiry

**Condition:** Any record the consumer cannot process.

## What it detects

Reports a stream event source mapping — Kinesis or DynamoDB Streams — whose
retry behaviour lets one unprocessable record hold a shard.

Two halves, and they fail differently:

- **Unbounded retries.** `MaximumRetryAttempts` and `MaximumRecordAgeInSeconds`
  both unset means Lambda retries the failing record until it expires from the
  source stream. Records behind it on the same shard wait the whole time.
- **A finite limit with nowhere to send the record.** Setting a retry limit
  without an `OnFailure` destination stops the stall by discarding the record,
  which converts a stall into silent loss.

The second is a `REQUIREMENT` with a `LOSS` impact and can block; the first is
the one no other tool reports.

## What the finding can carry

| Axis | Values this rule uses |
|---|---|
| `impact` | `STALL`, `LOSS` |
| `confidence` | `CONFIRMED`, `UNASSESSED` |
| `basis` | `REQUIREMENT` |
| Can it BLOCK under `--policy default`? | Yes — a finite limit with no on-failure destination |

`impact` is what breaks, `confidence` is how well the condition is known, and
`basis` is whether the threshold is AWS's rule or AWS's advice. The verdict is
computed from those three by the policy you choose — the rule never sets it.

## What it rests on

- [Handling errors for a Kinesis event source](https://docs.aws.amazon.com/lambda/latest/dg/with-kinesis.html)
- [Handling errors for a DynamoDB Streams event source](https://docs.aws.amazon.com/lambda/latest/dg/with-ddb.html)

## What it cannot know

Whether any record actually fails to process. The configuration is read
literally; what the handler does with a malformed record is not visible here.

## Also reported by

- `cfn-lint-serverless ES1001`

## Example

From `tests/fixtures/EDA005/violating.yaml`:

```text
[WARN] EDA005 - Poison record blocks the shard until expiry
  ClickMapping reads from ClickStream with MaximumRetryAttempts unset (infinite) and MaximumRecordAgeInSeconds unset (infinite). Required: a finite retry count or record age plus an OnFailure destination. Consequence: one unprocessable record is retried until source retention expires and later records on that shard wait behind it.
  basis: confirmed requirement | impact if it bites: stall
```

## Suppressing it

Suppressions live in the template, beside the resource they excuse. A reason is
mandatory, `expires` is honoured, and nothing is deleted — a suppressed finding
stays in the JSON report and is marked in SARIF.

```yaml
Resources:
  ClickMapping:
    Metadata:
      deadletter:
        ignore:
          - rule: EDA005
            reason: Why this is acceptable here, and who decided.
            expires: 2027-01-31   # optional
```
