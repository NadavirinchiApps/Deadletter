# EDA002 — Incomplete dead-letter coverage for a failing delivery

**Condition:** Any consumer failure that exhausts retries.

## What it detects

Follows each delivery path to a consumer that can fail, and reports the ones
with no dead-letter destination at the end of them.

Two kinds of failure are checked separately, because covering one is not
covering the other:

- **Transport failure** — the delivery service could not hand the event over.
  EventBridge answers this with a target `DeadLetterConfig`; SNS with a
  subscription `RedrivePolicy`; SQS with a `RedrivePolicy` and a finite
  `maxReceiveCount`.
- **Post-acceptance execution failure** — the event was delivered and the
  handler failed. Only a Lambda on-failure destination or DLQ catches that.

A path covered at one stage and not the other is reported, with the uncovered
stage named.

## What the finding can carry

| Axis | Values this rule uses |
|---|---|
| `impact` | `LOSS` |
| `confidence` | `CONFIRMED` |
| `basis` | `RECOMMENDATION` |
| Can it BLOCK under `--policy default`? | No |

`impact` is what breaks, `confidence` is how well the condition is known, and
`basis` is whether the threshold is AWS's rule or AWS's advice. The verdict is
computed from those three by the policy you choose — the rule never sets it.

## What it rests on

- [Asynchronous invocation](https://docs.aws.amazon.com/lambda/latest/dg/invocation-async.html)
- [Event retry policy and using dead-letter queues](https://docs.aws.amazon.com/eventbridge/latest/userguide/eb-rule-dlq.html)
- [Amazon SQS dead-letter queues](https://docs.aws.amazon.com/AWSSimpleQueueService/latest/SQSDeveloperGuide/sqs-dead-letter-queues.html)

## What it cannot know

Whether anything ever fails. A dead-letter destination is a safety net, and a
missing one is a missing net rather than a demonstrated loss — which is why this
rule is a `RECOMMENDATION` and cannot block under the default policy.

## Example

From `tests/fixtures/EDA002/violating.yaml`:

```text
[WARN] EDA002 - Incomplete dead-letter coverage for a failing delivery
  InvoicePaidRule delivers to LedgerFunction asynchronously, while neither the delivery service nor Lambda has a dead-letter destination. Required: dead-letter coverage for both transport failure and post-acceptance Lambda execution failure. Consequence: an event can be discarded at the uncovered stage with no replay path.
  basis: confirmed recommendation | impact if it bites: loss
```

## Suppressing it

Suppressions live in the template, beside the resource they excuse. A reason is
mandatory, `expires` is honoured, and nothing is deleted — a suppressed finding
stays in the JSON report and is marked in SARIF.

```yaml
Resources:
  InvoicePaidRule:
    Metadata:
      deadletter:
        ignore:
          - rule: EDA002
            reason: Why this is acceptable here, and who decided.
            expires: 2027-01-31   # optional
```
