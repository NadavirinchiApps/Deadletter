# EDA012 — Events are published to a hub with no delivery route

**Condition:** Every event published to this topic or bus.

## What it detects

Reports an SNS topic or EventBridge bus that accepts events and routes them
nowhere: no subscription, no rule with a target, nothing.

Both services accept a publish that matches nothing and return success. The
producer's metrics show delivery; no consumer ever runs. It is the one failure
mode in this pack with no error anywhere to find.

Two limits are stated on the finding rather than hidden behind a confident
message. A missing CloudFormation export is **not** proof of no external
consumer — a subscription in another stack can name the ARN directly, and needs
no export to do it. And the publish edge is usually IAM-derived, which shows a
producer *may* publish, not that it does. So the finding asks for confirmation
and stays `INFERRED`, except where the publisher is a state machine naming the
hub in its definition, which is a written fact rather than a permission.

## What the finding can carry

| Axis | Values this rule uses |
|---|---|
| `impact` | `LOSS` |
| `confidence` | `INFERRED`, `CONFIRMED` |
| `basis` | `REQUIREMENT` |
| Can it BLOCK under `--policy default`? | Yes — only when the publisher is a state machine naming the hub |

`impact` is what breaks, `confidence` is how well the condition is known, and
`basis` is whether the threshold is AWS's rule or AWS's advice. The verdict is
computed from those three by the policy you choose — the rule never sets it.

## What it rests on

- [Amazon SNS message delivery retries](https://docs.aws.amazon.com/sns/latest/dg/sns-message-delivery-retries.html)
- [Amazon EventBridge rules](https://docs.aws.amazon.com/eventbridge/latest/userguide/eb-rules.html)

## What it cannot know

Whether a consumer exists outside this scan. The finding says so in as many
words, and the coverage block lists the exports that make it likely.

## Also reported by

Nothing measured. See [the benchmark](../benchmark.md) for how that was
established, and against which versions of which tools.

## Example

From `tests/fixtures/EDA012/violating.yaml`:

```text
[WARN] EDA012 - Events are published to a hub with no delivery route
  AuditTopic has no subscription routing anything out of it, while RecordAuditFunction holds permission to publish to it, which does not establish that it does. Its ARN is also not exported, so this template shows no intended consumer anywhere. Required: at least one subscription delivering to a consumer, or confirmation that a consumer outside this template subscribes using the ARN directly — which needs no export and this scan cannot see. Consequence: if there is no such consumer, every published event is accepted, counted as delivered, and discarded because it matches no destination — the one failure mode that raises no error anywhere.
  basis: inferred requirement | impact if it bites: loss
```

## Suppressing it

Suppressions live in the template, beside the resource they excuse. A reason is
mandatory, `expires` is honoured, and nothing is deleted — a suppressed finding
stays in the JSON report and is marked in SARIF.

```yaml
Resources:
  AuditTopic:
    Metadata:
      deadletter:
        ignore:
          - rule: EDA012
            reason: Why this is acceptable here, and who decided.
            expires: 2027-01-31   # optional
```
