# EDA003 — Batch reprocessed wholesale on a single record failure

**Condition:** Any batch in which at least one record fails.

## What it detects

Reports an event source mapping that reads batches larger than one without
`FunctionResponseTypes: [ReportBatchItemFailures]`.

Without partial batch failure reporting, a batch either succeeds or fails as a
unit. One bad record in a batch of ten sends all ten back, including the nine
the handler already processed, and every retry repeats their side effects.

## What the finding can carry

| Axis | Values this rule uses |
|---|---|
| `impact` | `DUPLICATION` |
| `confidence` | `CONFIRMED`, `UNASSESSED` |
| `basis` | `RECOMMENDATION` |
| Can it BLOCK under `--policy default`? | No |

`impact` is what breaks, `confidence` is how well the condition is known, and
`basis` is whether the threshold is AWS's rule or AWS's advice. The verdict is
computed from those three by the policy you choose — the rule never sets it.

## What it rests on

- [Reporting batch item failures](https://docs.aws.amazon.com/lambda/latest/dg/services-sqs-errorhandling.html)
- [Using Lambda with Amazon Kinesis Data Streams](https://docs.aws.amazon.com/lambda/latest/dg/with-kinesis.html)

## What it cannot know

Whether the handler is idempotent. Whole-batch redelivery is documented AWS
behaviour; whether it is *harmful* depends on what the handler does with a
record it has already seen, which no template states. The message says so, and
the rule stays a `RECOMMENDATION`.

## Also reported by

Nothing measured. See [the benchmark](../benchmark.md) for how that was
established, and against which versions of which tools.

## Example

From `tests/fixtures/EDA003/violating.yaml`:

```text
[WARN] EDA003 - Batch reprocessed wholesale on a single record failure
  ShipFunction#FromQueue BatchSize is 10, while FunctionResponseTypes is unset. Required: ReportBatchItemFailures, unless ShipFunction is idempotent for these records. Consequence: one failing record fails the whole batch, so up to 9 records that already succeeded in ShipFunction are delivered again — duplicate side effects on every retry.
  basis: confirmed recommendation | impact if it bites: duplication
```

## Suppressing it

Suppressions live in the template, beside the resource they excuse. A reason is
mandatory, `expires` is honoured, and nothing is deleted — a suppressed finding
stays in the JSON report and is marked in SARIF.

```yaml
Resources:
  ShipFunction:
    Metadata:
      deadletter:
        ignore:
          - rule: EDA003
            reason: Why this is acceptable here, and who decided.
            expires: 2027-01-31   # optional
```
